# 応援の還元（クリエイター収益化・出金）設計

「応援された側（クリエイター）にお金を還元する」仕組みの全体像と、段階的な進め方。

## お金の流れ（モバイル）
```
[ファン] --IAP(消費型)--> [Apple/Google] --（手数料15〜30%控除）--> [運営(あなた)]
   --(残額からプラットフォーム手数料を控除)--> [クリエイター残高] --出金--> [クリエイター銀行口座]
```
- モバイルのデジタル投げ銭は **IAP必須**（外部決済は規約違反）。Apple/Googleが**15〜30%**徴収。
- 例: ¥500 応援 → ストア控除(30%)後 ¥350 → 運営手数料(例10%)¥35 → **クリエイター受取 ¥315**（目安）。
- 出金レール: **Stripe Connect（Express）** が定番（クリエイターはKYCを経て口座登録）。

## 必要コンポーネント
1. **レシート検証（サーバー）**：購入を Apple/Google サーバーで検証してから付与。
2. **台帳（ledger）**：
   - `gifts`: `{id, pinId, fromUid, toUid, gross, storeFee, platformFee, net, currency, createdAt, status}`
   - `balances/{uid}`: `{available, pending, lifetime}`
3. **クリエイター・オンボーディング**：Stripe Connect Express のアカウント作成リンク → KYC。
4. **出金**：最低出金額・スケジュール（手動/自動）・手数料。返金/チャージバック時は残高巻き戻し。
5. **管理/監査**：不正検知（自己応援禁止・異常検知）、税・帳票。

## 日本の法務（要・専門家確認）
- **資金決済法**：ユーザー間の送金を媒介すると **資金移動業登録** が必要になり得る。
  Stripe Connect 等の収納代行/プラットフォーム型で適切に設計すれば回避しやすいが要確認。
- **特定商取引法表記**、**景表法**、**インボイス/消費税**、クリエイター側の**所得（雑/事業）申告**、
  必要に応じ**支払調書**。**未成年の課金上限**。
- Apple の規約上、**IAP手数料は不可避**（デジタル投げ銭）。

## 段階的ロードマップ
- **Phase 1（推奨スタート・低リスク）: 換金なしの“エール”**
  応援は運営収益＋クリエイターには**バッジ/ランキング/特典**で還元（送金なし）。
  → 資金移動・KYC・出金の負担ゼロで公開可能。アプリ側はほぼ完成。
- **Phase 2: 収益ダッシュボード（見える化）**
  クリエイターに**総応援額・件数・推定受取額**を表示（出金はまだ）。本リポジトリで実装。
- **Phase 3: 実出金**
  レシート検証＋台帳＋Stripe Connect Express で出金。法務レビュー後に解放。

## アプリ側の実装状況（このリポジトリ）
- 収益ダッシュボード: `CreatorEarningsScreen`（総額/件数/推定受取/出金導線）。
- 受取額の推定: `PinProvider.myGrossEarnings` ×（1−ストア手数料−運営手数料）。
- 出金導線: Stripe Connect オンボーディングURLへ（バックエンド準備後に有効化）。

## 推定計算（既定の率は仮）
```
net ≈ gross × (1 − storeFee 0.30) × (1 − platformFee 0.10)
```
率は `CreatorEarningsScreen` 内の定数で調整可能。実際はストア/プラン/国で変動。
